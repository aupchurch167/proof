# A5 — Secrets and infrastructure

**Exec summary.** No `.env` is committed; `.env.example` is placeholders only. Client `VITE_*` vars are public by design and do not include server secrets. The gap is **no boot-time fail-loud** and **plaintext secrets in Postgres** (webhook signing keys, invite/reset/verify tokens). Droplet posture is unknown — checklist is `/audit/server-checklist.md` for the owner. This audit did **not** SSH anywhere.

---

ID:          A5-01
Title:       Process boots without required secrets
Severity:    High
Evidence:    `index.js:10-17` binds PORT and starts cron with no env schema. Required-at-runtime: `DATABASE_URL`, `JWT_SECRET`, `JWT_REFRESH_SECRET`. Optional-but-dangerous-if-missing: `RESEND_WEBHOOK_SECRET` (A2-02), `APP_URL` (cron builds `undefined/portal/...` — `cron.js:29`).
Impact:      Production can run “up” (health 200 against DB) while issuing unverifiable JWTs or sending broken portal links.
Fix sketch:  `src/config/env.js` zod parse; `process.exit(1)` on failure. File: new, called from `index.js`.
Effort:      S
Test:        Missing JWT_SECRET → exit 1, no listen log.

---

ID:          A5-02
Title:       Webhook secrets and user tokens stored plaintext
Severity:    Medium
Evidence:    `WebhookEndpoint.secret String` (`schema.prisma:324`). Reset/invite/verify columns are unique plaintext (`User` 131-133). API tokens **are** hashed (`ApiClient.tokenHash`, `lib/apiTokens.js:15-17`) — good.
Impact:      A read-only DB dump (support export, stolen Neon credential, overly broad replica) yields every customer’s outbound-webhook HMAC key and every outstanding invite/reset link.
Fix sketch:  Hash webhook secrets the way API tokens are hashed **or** encrypt with a KMS key. Hash invite/reset/verify (lookup by sha256 of the presented token). Files: `schema.prisma`, `integrations.js`, `auth.js`, `users.js`.
Effort:      M
Test:        `GET` webhook list never includes secret (already). DB row after create is not equal to the shown-once secret.

---

ID:          A5-03
Title:       .gitignore covers `.env` only
Severity:    Low
Evidence:    `/workspace/.gitignore` lines 1-6: `node_modules/`, `dist/`, `.env`, `*.log`, `uploads/*`. No `.env.*`, `*.pem`, `server/.env.local`. `git ls-files` shows only `server/.env.example` and `client/.env.example`. No live `.env` files were present in this workspace.
Impact:      A future `.env.production` copy-paste is committable. Today nothing leaked.
Fix sketch:  Add `.env.*`, `!.env.example`, `*.pem`. File: `.gitignore`.
Effort:      S
Test:        `git check-ignore -v server/.env.production` matches.

ID:          A5-04
Title:       Staging environment not described
Severity:    Unverified
Evidence:    CORS lists localhost, `app.proofcoi.com`, `proof.up.railway.app` (`app.js:55-59`). No `staging.proofcoi.com`. No second Nginx server block.
Impact:      If Railway is leftover staging, it is a second production-like origin with credentials CORS. If there is no staging, every test is on prod.
Fix sketch:  Owner states the environments. Remove unused origins.
Effort:      S (owner)
Test:        Documented matrix: local / staging / prod, each with its own JWT secrets and Spaces bucket.

ID:          A5-05
Title:       Git history secret scan (limited) found no live keys
Severity:    Low
Evidence:    Commands in `/audit/NOTES.md`. 107 commits. Tracked env-like files: `.env.example` only. Regex for `AKIA…`, `sk_live_`, `sk-ant-`, PEM headers: no matches in tracked non-markdown files except `whsec_` **generation** code and tests (`whsec_test`). gitleaks/trufflehog were **not installed**.

Effort:      S
