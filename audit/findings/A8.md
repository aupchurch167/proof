# A8 — Feature completeness

**Exec summary.** The core loop (vendor → request COI → portal upload → AI extract → review → reminders) is built and has tests. Launch is blocked by **security/durability holes**, not by a missing vendor list screen. Several product surfaces are stubs (billing, per-trade templates, MFA, export/offboarding, ToS).

Walked from code + `docs/testing-checklist.md` + `docs/api-v1.md` (no live browser; no production).

## Flows that exist in code

- Signup / login / Google / invite / forgot-reset / verify-banner
- Vendor CRUD, bulk delete, CSV import, public apply
- COI upload (admin + portal + inbound email), extract, edit, approve/reject, reanalyze
- Request-COI email + 24h cooldown + chase ladder + weekly summary
- Compliance cockpit + reminders upcoming + audit log + replies feed
- Requirements (single default template) + coverage period JSON
- Reports: compliance counts, coverage timeline, expiring, PDF merge
- Integrations: per-org API keys + outbound `coi.updated`
- v1 public API for vendors / COI requests / historical COIs + signed PDFs
- Plan meter (display + some enforce)

## Blocks launch

These are not “nice to have.” Shipping commercial multi-tenant SaaS with them open is an incident waiting for the second customer.

1. **A2-01 / A2-02** — inbound webhook cross-tenant + optional auth
2. **A2-03** — confirm Core flag is off (or gate it)
3. **A1-02 / A1-03** — verify-email gate + Google link rules
4. **A1-13 / A2-04** — portal token leakage + unused JWT verify
5. **A3-01** — one successful restore rehearsal
6. **A5-01 / A6-01** — boot env fail-loud + Sentry
7. **A10-01** — ToS + privacy URLs on signup
8. **A2-05** — apply by UUID + no plan limit
9. **A9-01** — CI that runs `server` Jest on every PR
