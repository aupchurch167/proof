# A9 — Tests and CI

**Exec summary.** Server Jest is real and the v1/integrations suites already do two-tenant checks. There is **no CI**. App-route tests are single-org happy paths. `portal.test.js` disagrees with `portal.js`. `cleanupTestData()` truncates the whole database.

---

ID:          A9-01
Title:       No CI workflow
Severity:    High
Evidence:    No `.github/`, no `*.yml` workflow, no Circle/Buildkite config (`glob **/*.{yml,yaml}` → 0 files). Tests exist: `server/package.json:12` `jest --runInBand`.
Impact:      A PR can merge a broken tenant filter or a failing suite. The v1 isolation tests only help if someone runs them.
Fix sketch:  GitHub Action: `npm ci` at root, `cd server && npm test`, Node 22. Do not point DATABASE_URL at prod (A9-05). File: `.github/workflows/test.yml`.
Effort:      S
Test:        Open a PR that fails an expect → CI red.

---

ID:          A9-02
Title:       Session API has almost no two-tenant tests
Severity:    Medium
Evidence:    Two-tenant coverage today: `api-v1.test.js` (403 other org, 404 other COI), `integrations.test.js:80-88`, `compliance.test.js:312-321`, `webhook-dispatch.test.js` org A vs B endpoints. `vendors.test.js` / `cois.test.js` / `auth.test.js` create one org. Proposed cases: `/audit/tenant-isolation-tests.md`.
Impact:      A2-01 would not have been caught by the current suite.
Fix sketch:  Add `describe('tenant isolation')` to vendors, cois, portal, apply, webhooks, organization/usage, users. Reuse `createTestOrg` × 2 from `setup.js`.
Effort:      M
Test:        File-level: every tenant-scoped route has a “404/empty for org B token” case.

---

ID:          A9-03
Title:       portal.test.js expects 401; portal.js returns 404
Severity:    Medium
Evidence:    `portal.test.js:37-44,68-74` `expect(res.status).toBe(401)` for `invalid-token-string`. `portal.js:46-47,81-82` `res.status(404)`. Either tests are not run in CI (A9-01) or JWT_SECRET in the test env makes a different branch — there is no jwt.verify in the route, so 404 is what production does.
Impact:      The suite is already red or is skipped. False confidence.
Fix sketch:  Align on 401 after A1-13 (verify JWT) **or** change tests to 404. Files: `portal.test.js`, `portal.js`.
Effort:      S
Test:        `npm test -- portal.test.js` green against current server.

ID:          A9-04
Title:       No client tests
Severity:    Low
Evidence:    `client/package.json` scripts: `dev`, `build`, `preview` only.
Impact:      AdminRoute regressions and token-storage bugs will not be caught. Server authorize() is the real control; this is hygiene.
Fix sketch:  Vitest + one test that `api.js` sends Authorization. Not a launch blocker.
Effort:      M
Test:        `npm test` in client exits 0.

---

ID:          A9-05
Title:       Jest setup deletes every row in every table
Severity:    Medium
Evidence:    `server/tests/setup.js:99-111` `deleteMany({})` on audit, coiRequest, notification, coi, vendor, webhook, apiClient, user, settings, organization — **no org filter**.
Impact:      `npm test` against a developer’s Neon branch or (worse) a copied DATABASE_URL wipes customers.
Fix sketch:  Prefix test emails/slugs; delete `where: { email: { endsWith: '@test.com' } }` or require `DATABASE_URL` to contain `test`. File: `tests/setup.js`.
Effort:      S
Test:        Second org named `keep-me` survives `cleanupTestData` if not created by the suite — or suite refuses to start without `PROOF_TEST_DB=1`.

## Top 10 untested high-risk paths

1. `POST /api/webhooks/resend-inbound` two orgs, same vendor email (A2-01)
2. Unsigned inbound webhook when secret set / unset (A2-02)
3. `GET /api/vendors` as org B must not include org A rows (implied, not asserted)
4. `GET /api/organization/usage` must not return another org’s token; should not return token at all (A2-04)
5. `POST /api/apply/:uuid` (A2-05)
6. `PUT /api/portal/:token/info` after JWT expiry (A1-13)
7. Google login against unverified password user (A1-03)
8. `POST /api/auth/refresh` after user delete / logout (A1-01)
9. `HELM_CORE_INTEGRATION=true` create vendor in org ≠ CORE (A2-03)
10. `POST /api/reports/export-pdfs` with another org’s coiIds (filter exists, no test)
