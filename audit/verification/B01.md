## Overall recommendation: **merge**

The three Criticals (A2-01, A2-02, A2-03) and the High attachment-SSRF / boot / timeout items are fixed for the attacks in the batch. An outsider cannot fan inbound mail or bounces across tenants, cannot fetch arbitrary attachment URLs, and cannot dump every tenant into one Core org when the new gates are used as documented.

Do **not** send back. Residuals below are fail-closed, operator-misconfig, or defense-in-depth gaps that the original finding’s own test already did not require. None restore the original cross-tenant write or “register `http://169.254…` as an org admin” attacks.

No migrations in the fix PR. No data-loss risk.

## Per-finding verdicts

### A2-01 — Inbound matches every vendor sharing an email — **Verified**

**Original:** `vendor.findMany({ email })` then write COI + `vendor_reply` on every org.

**This branch:** `correlateInboundVendor` (`server/src/routes/webhooks.js:287-317`) takes the latest SENT `UPLOAD_REQUEST` for that `recipientEmail` (90d), then loads **that** vendor in **that** `orgId`. No global `findMany` by email. No correlation → log and skip (`252-256`).

**Repro (official WH-1):** two orgs, shared `shared@sub.com`, A sent last request → COI + audit only on A. Passed (`server/tests/webhooks-inbound.test.js:84-114`).

**Tried to break it:**

| Case | Result |
|---|---|
| No `UPLOAD_REQUEST` at all | `200 { matched: 0 }`, zero COI/audit on A or B |
| Last request on A; From = B’s `additionalEmails` | skip, zero rows |
| Last request on A; From = A’s `additionalEmails` | skip (From is not the stored `recipientEmail`) |
| CC/To of the other tenant, From = shared email | audit only on A (`matched: 1`), B untouched |
| Forged From = shared email (valid Svix) | files **only** the last requesting org — last-writer-wins, not multi-match |

**Residual (fail-closed, already in `audit/findings/new.md`):** inbound from a CC / `additionalEmails` address is ignored unless that address was itself the SENT `recipientEmail`. `POST /api/vendors/:id/request-coi` CCs `additionalEmails` but stores `recipientEmail: vendor.email` only (`vendors.js:520-531`). That is a product miss, not a cross-tenant write.

**Test quality:** WH-1 asserts the isolation property (A has the row, B does not), not just HTTP 200.

### A2-02 — Inbound webhook auth optional — **Verified**

**Original:** `if (RESEND_WEBHOOK_SECRET && !verify) 401` — unset secret processed unsigned traffic. Route still sits before the rate limiter (`app.js:65-75`).

**This branch:**

- Secret set → always Svix-verify (`webhooks.js:189-194`).
- Secret unset + `NODE_ENV === 'production'` → **503**, no handler (`195-197`).
- Boot: `validateEnv` requires the secret when `NODE_ENV === 'production'` (`config/env.js:32-38`); `index.js:4-8` `process.exit(1)`.

**Repro:**

- Official WH-2: secret set, unsigned POST → **401**, COI/audit counts unchanged. Passed (`webhooks-inbound.test.js:117-127`).
- Probe: secret unset + `NODE_ENV=production` → **503**, `coiDelta 0`.
- Probe: spawn `src/index.js` with `NODE_ENV=production` and no secret → exit **1**, `RESEND_WEBHOOK_SECRET is required in production`.

**Tried to break it — Svix is still skippable off the exact production string:**

| Env | Secret | Boot | Unsigned POST |
|---|---|---|---|
| `NODE_ENV=production` | unset/empty | exit 1 | 503 (if process were up) |
| `NODE_ENV=development` / `test` / unset | unset | boots | **200, processes** |
| `NODE_ENV=Production` | unset | **boots** (`Proof server running on port 3998`) | **200, processes** |
| `NODE_ENV=prod` / `PRODUCTION` / ` production` | unset | `validateEnv` accepts | would process |

So yes: Svix is skippable in non-prod **by design** (`.env.example:22-24`). That can reach a production-shaped deploy **only if `NODE_ENV` is not exactly `production`** (including the common typo `prod` / `Production`, or forgetting the var). Railway/PM2 convention is lowercase `production`; the deploy notes on PR #10 already require the secret before this build.

**Not send-back.** The finding’s contract was `NODE_ENV=production`. WH-2 asserts the security property (401 + zero rows). Missing: no test for the 503 path or `NODE_ENV` aliases.

### A2-03 — Core mirrors every tenant into one `CORE_ORG_SLUG` — **Verified**

**Original:** `HELM_CORE_INTEGRATION=true` posted every create to `/api/v1/orgs/${CORE_ORG_SLUG}/vendors`.

**This branch:** `isEnabled()` is `=== 'true'` (unset/false is off). `resolveMappedCoreSlug` (`lib/core.js:37-55`):

- If `CORE_ORG_MAP` parses to an object, only `map[org.id]` or `map[org.slug]`.
- If the map is **unset/blank**, fallback is `org.slug === CORE_ORG_SLUG` — **not** “every org → that slug.”
- Invalid JSON / non-object map → `{}` (fail-closed, no slug fallback).

Create/import/compliance paths call `shouldMirror(vendor)` before `createVendor`/`updateVendor(..., vendor)`.

**Repro (official J-03):** flag on, `CORE_ORG_SLUG=orgA`, map unset, create vendor in org B → `core.createVendor` **not** called. Create in org A → called once with `orgId === orgA`. `shouldMirror` false for an org missing from `CORE_ORG_MAP`. Passed (`server/tests/core-mirror.test.js`).

**Asked check — map unset, slug set, multiple orgs:** probe `shouldMirror({orgId: A}) === true`, `shouldMirror({orgId: B}) === false`. **Does not leak all tenants.**

Production: `buildHeaders` (`core.js:62-84`) sends `Authorization: Bearer` only; no `x-helm-test-*`. Missing `CORE_API_TOKEN` throws at call time (caught by `mirrorCreateToCore`). Probe confirmed.

**Residual (not the original dump):** `updateVendor` / `listVendors` without a vendor still use `CORE_ORG_SLUG` (`core.js:152-161`). `mirrorDeleteToCore` (`vendors.js:172-178`) calls `updateVendor(coreId, { status: 'inactive' })` with **no vendor**, so a delete of a linked vendor PATCHes `…/orgs/${CORE_ORG_SLUG}/vendors/${coreId}`. Documented in `audit/findings/new.md`. App create/update/import used by the product pass the vendor. Non-prod still sends test-bypass headers.

**Test quality:** J-03 spies `createVendor` (the gate the route uses) and asserts “B does not call.” Fire-and-forget wait is a bit soft (50–500ms) but the spy did fire for the mapped org.

### A2-08 — Bounce flips another tenant’s `NotificationLog` — **Verified**

**Original:** `findFirst({ recipientEmail, SENT, 7d })` with no org / no Resend id.

**This branch:** `correlateFailureLog` (`webhooks.js:360-388`) prefers `meta.emailId === payload.email_id`. If that misses, loads recent SENT rows and **skips unless exactly one distinct `orgId`**.

`request-coi` stores `meta.emailId` from Resend (`vendors.js:530`; `email.js` now returns `{ id: data?.id }`).

**Repro (official WH-3):** shared recipient, `email_id=re_org_a` → only A’s log becomes `FAILED`. No `email_id` + two orgs SENT → both stay `SENT`. Passed.

**Tried to break it:** unknown `email_id` + two orgs SENT → both stay `SENT` (falls through to the multi-org skip). Solo-org SENT without `email_id` → that org’s latest row flips (same-tenant, acceptable).

**Residual:** cron / chase / v1 / rejection rows still do not persist `emailId` (`cron.js:116,218`). Ambiguous bounces without id are skipped (fail-closed). WH-3 asserts the isolation property.

### A4-01 — Attachment URL SSRF — **Verified**

**Original:** `fetch(att.url)` with no scheme/host/timeout/private-IP check.

**This branch:** `assertSafeAttachmentUrl` (`safeUrl.js:88-94`) requires `https:` **and** `resend.com` / `*.resend.com`, rejects credentials and IP literals. Pre-check in `handleInbound` (`webhooks.js:241-249`) returns **400** before correlation/fetch. `materializeAttachment` checks again and uses `fetchWithTimeout(..., { redirect: 'error' }, 5000)` (`87-103`).

**Repro:** official case `http://127.0.0.1:4000/api/health` → 400, `fetch` not called. Passed.

**Tried to break it:**

| URL | Status | fetch |
|---|---|---|
| `https://169.254.169.254/latest/meta-data/` | 400 | 0 |
| `https://evil.example/file.pdf` | 400 | 0 |
| `https://resend.com.evil.test/file` | throw (unit) | — |
| `https://evil-resend.com/file` | throw | — |
| `https://resend.com@evil.example/file` | credentials rejected | — |
| `http://attachments.resend.com/file` | not https | — |
| `https://[::ffff:127.0.0.1]/file` | not allowlisted | — |
| `https://attachments.resend.com/file.pdf` | allowed (unit + hostname) | only after org correlation |

IPv6 tricks do not matter here: host must be `*.resend.com`. Redirects are not followed. Uncorrelated inbound never reaches `fetch` even for an allowlisted host (probe: resend URL + no SENT log → 200 `matched: 0`, fetch 0).

**Test quality:** official test asserts **no fetch**, not just 400. `safe-url.test.js` covers suffix bypass (`resend.com.evil.test`). Missing: https metadata IP and redirect-mode in the suite (probed here).

### A4-02 — Org admin registers `http://` webhook (SSRF) — **Verified** (dispatch IPv6 residual)

**Original:** `/^https?:\/\//` allowed `http://127.0.0.1` / metadata. CLI had no scheme check.

**This branch:**

- **Write (API):** `assertPublicHttpsUrl` (`integrations.js:145-149`) — https, no credentials, blocked hostnames, **DNS resolve**, reject if any address is private.
- **Write (CLI):** same helper (`scripts/create-webhook-endpoint.js:59-64`).
- **Dispatch:** `parseHttpsUrl` only (`webhookDispatcher.js:19-29`) — scheme / hostname / IP **literals**. No DNS re-resolve (already noted in `audit/findings/new.md`).
- PUT cannot change `url` (only `active`).

**Repro:** official integrations test: `http://127.0.0.1/` and `https://169.254.169.254/` → 400; `https://example.com/hooks` → 201. Passed.

**Write-time probe (API):** `http://127.0.0.1/`, `https://127.0.0.1/`, `https://169.254.169.254/`, `https://[::1]/hook`, `https://[::ffff:169.254.169.254]/` → all **400**. `https://example.com/hooks` → 201.

**Dispatch-time probe (row inserted, then `emitCoiUpdated`):**

| Stored URL | Delivery | fetch |
|---|---|---|
| `http://127.0.0.1/` | `failed:blocked-url` | 0 |
| `https://127.0.0.1/` | `failed:blocked-url` | 0 |
| `https://example.com/hooks` | success | 1 |
| `https://[::1]/hook` | **success** | **1** |
| `https://[::ffff:127.0.0.1]/hook` | **success** | **1** |
| `https://[::ffff:169.254.169.254]/` | **success** | **1** |

Root cause: WHATWG `URL` keeps brackets (`hostname === "[::1]"` / `"[::ffff:7f00:1]"`). `net.isIP('[::1]') === 0`, so `isBlockedIp` / `isBlockedHostname` never see an IP (`safeUrl.js:48-61,77`). Write-time still rejects these because `dns.lookup('[::1]')` fails (“host could not be resolved”). Dispatch never looks up DNS, so a **pre-existing** or **hand-inserted** IPv6-literal row would POST to loopback/metadata.

Org admin **cannot** create that row through API or CLI. `http://` is rejected at **both** write and dispatch.

**Test quality:** write-time test asserts the finding’s own cases. `webhook-dispatch.test.js` is happy-path / org-scoping only — it does **not** assert `failed:blocked-url` or “no fetch.” `safe-url.test.js` never uses a bracketed IPv6 literal.

**Residual / follow-up (do not block merge):** strip `[]` before `net.isIP`, and/or re-resolve at send. DNS rebinding of a hostname that was public at create remains (documented).

### A5-01 / A1-05 — Process boots without required secrets — **Verified**

**Original:** `index.js` listened with no schema. `JWT_SECRET` could be missing/placeholder.

**This branch:** `validateEnv` (`config/env.js`) requires `DATABASE_URL`, `APP_URL`, JWT pair ≥32 chars and not the `.env.example` placeholders, and `RESEND_WEBHOOK_SECRET` when `NODE_ENV === 'production'`. Wired first thing in `index.js:1-8`.

**Repro:** official `env.test.js` — missing/short JWT, missing DB/APP_URL, placeholder, prod webhook secret. Passed.

**Process-level (spawn `src/index.js`):**

- Unset / short `JWT_SECRET` → exit 1, no listen.
- `NODE_ENV=production` without webhook secret → exit 1.
- `NODE_ENV=production` + webhook secret → listens (`Proof server running on port 3999`).

**NODE_ENV tricks:** `validateEnv` uses strict `=== 'production'`. `Production` / `prod` / `PRODUCTION` / leading space / unset all **accept** a missing webhook secret, and `index.js` will listen. Same alias hole as A2-02. `CORE_API_TOKEN` is **not** a boot requirement (A2-03 enforces it at call time in production). Weak 32-char secrets (`aaaa…`) pass — out of finding scope.

Official tests unit-test `validateEnv` rather than `process.exit`; the spawn above closes that gap.

### A6-02 — Core / inbound fetch have no timeout — **Verified**

**Original:** `core.js` and `materializeAttachment` used bare `fetch`.

**This branch:** shared `fetchWithTimeout` (default 5s, `AbortController`) used by Core (`core.js:88-92`) and inbound downloads (`webhooks.js:101`). Outbound customer webhooks already had a 5s abort (`webhookDispatcher.js:31-32`) and still do (not switched to the helper — not a regression).

**Repro:** `fetch-timeout.test.js` advances fake timers 5s and expects `AbortError`. Passed. Grep of `server/src` shows no other bare `fetch(` besides the dispatcher and the helper.

**Test quality:** asserts the timeout property, not a successful Core call.

## Merge vs send-back

**Merge PR #10.**

Reasons:

1. WH-1/2/3 and J-03 — the batch’s own isolation cases — pass and match the code.
2. Adjacent attempts (no request, extra emails, CC, unknown bounce id, non-Resend attachment hosts, unmapped Core org) fail **closed**.

4. Boot actually exits before listen without JWT / prod webhook secret.
5. Residuals are documented, mostly fail-closed, and are not the original Criticals.

**Do not silently patch** the IPv6 dispatch parse or `NODE_ENV` aliases in a verify PR. If a follow-up is wanted, open it on the fix branch after merge: strip brackets in `isBlockedHostname`, add a dispatch test that `https://[::1]/` does not `fetch`, and treat `prod`/`Production` like production for the webhook secret.
