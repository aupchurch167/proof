### A4-03 — Transactional emails interpolate unsanitized org/vendor/reason HTML — **Verified**

**Original:** `orgName`, `orgAddress`, `vendorName`, rejection `reason` inserted into HTML strings. ADMIN-controlled org name / portal vendor name / reject reason could inject `</a><script>` or tracking pixels into mail to other vendors and admins.

**This branch:** `escapeHtml` (`&`, `<`, `>`, `"`, `'`) wraps every user-controlled interpolation in `server/src/services/email.js` before it enters an HTML body. Subjects keep the raw string (plain text). `sendEmail` still sends `{ to, from, subject, html }` only.

```7:14:server/src/services/email.js
function escapeHtml(value) {
  return String(value ?? '')
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#39;');
}
```

**Repro (official):** org name `<img src=x onerror=alert(1)>` appears as `&lt;img …&gt;` in the Resend HTML; raw `<img` is absent; vendor `<b>` is escaped. Passed.

**Tried to break it:**

| Builder | HTML body | `text` part |
|---|---|---|
| `sendUploadRequestEmail` (`<script>` org, `<img` address, `</a><script>` vendor) | tags escaped; no `<script` / `<img ` | **none** |
| `sendChaseEmail` (`<img` org) | escaped | none |
| `sendUploadNotificationEmail` | escaped vendor | none |
| `sendRejectionEmail` (`<img` reason) | escaped | none |
| `sendExpirationReminderEmail` | escaped | none |
| `sendInviteEmail` | escaped org + URL | none |
| `sendWeeklySummaryEmail` (XSS org + vendor row) | escaped | none |
| Subject of upload-request | **raw** `<script>alert(1)</script>` (plain text, as designed) | — |
| `escapeHtml(\`&<>"'\`)` | `&amp;&lt;&gt;&quot;&#39;` | — |

**Plain-text path (asked check):** there is **no** `text` / `text/plain` alternative. Clients that synthesize plaintext from HTML will see entities (`&lt;img`), not live tags. That is safe. It is not a multipart `text/plain` part.

**Residual:** subjects are unescaped by design (STATUS). `javascript:` in a server-built portal URL would still be a valid `href` after entity-escaping — URLs here are minted by the app / `APP_URL`, not taken from the vendor. `mailto:${orgEmail}` uses the escaped address (a `"` in an org email becomes `&quot;`).

**Test quality:** official case asserts the HTML property (escaped vs raw), not just “send was called.” It covers one builder. The other six were probed here.

### A4-04 — Claude extraction has no spend cap — **Verified**

**Original:** full PDF to Sonnet, `max_tokens: 4096`, no per-org daily cap, no size check beyond multer 10MB. Public apply + inbound webhook could drive spend.

**This branch:** `assertExtractAllowed` then `recordExtract` in `extractCoiData`. Defaults: `EXTRACT_MAX_BYTES=4194304` → **413** `EXTRACT_BYTE_LIMIT`; `EXTRACT_DAILY_CAP=10` → **429** `EXTRACT_DAILY_CAP`. Count is `AuditLog` `action=extract` / `entity=ai` since UTC midnight (no migration). `if (!orgId) return` skips the **daily** cap only. Every request-path caller passes `orgId` (admin upload, portal, apply, reanalyze, inbound webhook). Apply pre-checks the cap **before** `vendor.create`. Webhook catches the limit error, logs, and still 200s Resend.

```33:58:server/src/services/coiExtractor.js
async function assertExtractAllowed(orgId, byteLength) {
  const maxBytes = getExtractMaxBytes();
  if (byteLength > maxBytes) {
    throw new ExtractLimitError(
      `PDF exceeds the AI extract size limit (${maxBytes} bytes)`,
      { status: 413, code: 'EXTRACT_BYTE_LIMIT' }
    );
  }
  if (!orgId) return;
  // AuditLog count for this UTC day vs EXTRACT_DAILY_CAP
```

**Repro (official):** oversized buffer → 413 on `extractCoiData` and on `POST /api/vendors/:id/coi/upload`; 10 planted rows then 11th → 429. Passed.

**Tried to break it:**

| Case | Result |
|---|---|
| `assertExtractAllowed(org, 4MB)` | **allowed** |
| `assertExtractAllowed(org, 4MB+1)` | **413** `EXTRACT_BYTE_LIMIT` |
| Org A at cap; org B assert | A **429**; B **allowed** (tenant-scoped) |
| `AuditLog` from 36h ago only | **allowed** (UTC day window) |
| `orgId` null/undefined, tiny PDF | daily cap **skipped** (byte cap still 413) |
| Portal JWT upload at cap | **429**, COI count unchanged |
| Apply + PDF at cap | **429**, vendor count unchanged |
| Reanalyze at cap | **429** |
| Webhook + `%PDF-` at cap | **200**, warn `EXTRACT_DAILY_CAP`, no Resend failure |

**Concurrent overshoot (asked check, already in STATUS):** count-then-insert. Two overlapping `assertExtractAllowed` at 9 can both proceed and record 11. Acceptable; no unique constraint was added (batch: no migration). Failed Anthropic **after** `getClient()` still consumes a slot (`recordExtract` is before `messages.create`). `getClient()` throw (missing key) is **before** `recordExtract`, so a missing key does not burn a slot.

**Residual:** `server/scripts/import-airtable-cois.js` still calls `extractCoiData(buf)` with no `orgId` (operator script, not the HTTP path). Admin/portal `uploadFile` to Spaces happens **before** extract — a 429/413 can leave an orphan object (COI row is not created; probed on portal). Not send-back.

**Test quality:** official cases assert `status` + `code` on both the helper and the admin route. Portal/apply/reanalyze/webhook/cross-org were only probed here.

### A4-05 — Most mutating routes have no zod body schema — **Verified**

**Original:** unvalidated google, forgot-password, vendor PUT, settings PUT amounts, apply POST. Type confusion on settings amounts could 500. Privileged keys `plan` / `role` / `orgId` were the mass-assignment concern.

**This branch:** schemas `updateSettings`, `updateVendor`, `google`, `forgotPassword`, `applyVendor`. `parseSchema` rejects privileged keys **before** `safeParse`. Settings / vendor PUT / google / forgot use `validate()`; apply uses `parseSchema` on the multipart body and then **`parsed.data`** (unknown keys stripped).

```103:118:server/src/utils/validation.js
function privilegedKeyError(body) {
  if (!body || typeof body !== 'object') return null;
  const found = PRIVILEGED_BODY_KEYS.filter((key) => Object.prototype.hasOwnProperty.call(body, key));
  if (!found.length) return null;
  return `${found.join(', ')} cannot be set`;
}
```

**Repro (official):** settings `{minGeneralLiability:'x'}` → **400** not 500; vendor PUT bad email → 400; google `{credential, plan:'UNLIMITED'}` → 400 `/plan/i`; forgot + apply non-email → 400. Passed. Existing `settings.test.js` chase-day case still **200** `[2, 5, 10]`.

**Tried to break it:**

| Case | Result |
|---|---|
| settings `plan` / `role` / `orgId` (alone or with a valid amount) | **400** `cannot be set`; org.plan unchanged |
| vendor PUT `{name, orgId, role, plan}` | **400**; vendor stayed on org A, name unchanged |
| vendor PUT `{name, uploadToken, deletedAt, coreId}` | **200**; name updated; token/deletedAt/coreId **not** written (handler destructures allow-listed fields) |
| google `{credential, role, orgId}` | **400** |
| forgot `{email, orgId}` | **400** |
| apply multipart `plan` + `orgId` | **400** |
| organization PUT `{plan:'UNLIMITED'}` (adjacent, not a batch schema) | **200**, plan stays **FREE** (field ignored) |
| settings `{minGeneralLiability: 100000000}` | **200** |

**Mass-assignment (asked check):** `plan` / `role` / `orgId` are rejected on the five routes. Settings and vendor handlers never spread `req.body` into Prisma. Apply uses parsed data only. Google hard-codes `role: 'ADMIN'` and creates its own org.

**Residual (not send-back):** `validate()` does **not** assign `req.body = result.data`, so unknown non-privileged keys remain on the object. Harmless today because those handlers destructure. Finding also listed request-coi, users invite, integrations, portal PUT, import `headerMap` — batch work item 3 named only the five routes. ### A4-07 — Upload allow-list is MIME type only — **Verified**

```3:14:server/src/utils/uploadFilters.js
function hasPdfMagic(buffer) {
  return Buffer.isBuffer(buffer) && buffer.length >= PDF_MAGIC.length
    && buffer.subarray(0, PDF_MAGIC.length).equals(PDF_MAGIC);
}
```

**Repro (official):** admin upload MIME pdf + `MZ…` → 400 `/valid PDF/i`. Passed.

| Webhook PDF MIME + `MZ` + matching SENT request | **200** `matched: 1`; COI count **unchanged** (stored as reply attachment, not auto-COI) |
