# B02 — Authn, invites, portal capability leak

**Goal:** Unverified signups cannot operate a tenant; portal URLs are not sitting on every GET; Google cannot attach to unverified rows.

**Includes:** A1-01 (minimum viable: revoke on password reset + logout endpoint), A1-02, A1-03, A1-04, A1-09, A1-11, A1-13, A2-04, A2-05, plus cheap A1-06, A1-10, A1-12

**Files:** `routes/auth.js`, `routes/users.js`, `routes/portal.js`, `routes/vendors.js`, `routes/organization.js`, `routes/apply.js`, `utils/tokens.js`, `middleware/auth.js`, `Layout.jsx`, `AuthContext.jsx`, `prisma/seed.js`

## Work

1. `requireVerified` on `/api/*` except auth + portal + apply + webhooks + health + import templates (A1-02). Set `emailVerified` on accept-invite (A1-09).
2. Google link only if `emailVerified` or existing `googleId` (A1-03).
3. Stop returning `inviteToken` and `uploadToken`. Drop `portalPreviewToken` or ADMIN-only mint (A1-04, A2-04).
4. Invite expiry (48h) + hash at rest if cheap (A1-04).
5. Call `verifyUploadToken` on all portal routes (A1-13).
6. Apply: slug only + plan limit (A2-05).
7. `validate('updateProfile')`; email change re-verify (A1-11).
8. Logout + password-reset invalidate refresh (A1-01 — Session table or denylist).
9. Generic signup 409 (A1-06); seed guard (A1-10); `algorithms: ['HS256']` (A1-12).
